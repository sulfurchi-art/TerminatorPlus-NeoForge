# 4.14 卓越前线枪械与载具内测

适配 **Superb Warfare 0.8.9.1-final-mc1.21.1**，对应源码提交 `5b92ebe1da5daad9cc5e8ae28e3e06f1636f5816`。本轮根据 4.13 实测反馈修正换弹、世界边界、近距离载具攻击及反坦克打法，并加入可选的卓越前线分级配装。已有同队乘员组、座位武器与直升机操控继续保留。没有安装卓越前线时，TerminatorPlus 仍可独立运行；其他卓越前线版本会禁用此兼容层，可在 `/bot info <名字>` 查看状态。

卓越前线这个版本自身要求 NeoForge **21.1.203 及以上**，用户的 21.1.249 符合要求。TerminatorPlus 单独运行时仍兼容 21.1.1，下限没有改变。卓越前线与它的依赖按自身要求安装；TerminatorPlus 仍只需放在服务端。

## 开始测试

先准备自己的枪械、配件和弹药，并空出一个背包格，保存成预设：

```mcfunction
/bot preset save warfare
/bot createpreset warfare RifleBot 7 none
/bot settings ability guns true
/bot settings setgoal nearestvulnerableplayer
/bot info RifleBot
```

预设沿用玩家真实枪械组件、已装弹匣和备弹物品。生成要等皮肤请求完成；可通过 `/bot count` 确认生成。准备多个枪种时，机器人会根据距离选择已有武器。

也可在机器人已经生成后发放基础步枪和有限弹药。以下库存指令影响所有现有机器人：

```mcfunction
/bot inventory give superbwarfare:ak_47 1
/bot inventory give superbwarfare:rifle_ammo 64
```

不要使用 `/bot give` 配枪，它设置的是默认近战显示武器；枪必须在真实背包中。也不要用普通 `/give` 将物品塞进会被 AI 覆盖的第 0 格。单独配装可以使用 `/item replace entity RifleBot hotbar.1 with superbwarfare:ak_47` 等原有指令。

关闭兼容动作：`/bot settings ability guns false`。它会归还真实枪械，恢复原有近战和其他技能。预设也可用 `/bot loadout profile warfare ability guns false` 保存单个套装的覆盖。

## 两套独立默认配装

选择默认配装影响之后生成、没有使用自定义预设的机器人；设置会保存。自定义预设仍优先。

```mcfunction
/bot preset use none
/bot settings defaultgear true
/bot settings gear warfare
/bot settings hardness 7
# 切回原版套装
/bot settings gear vanilla
# 替换已有机器人的装备，AI 难度保持不变
/bot inventory default warfare 7 RifleBot
```

除通用图腾、鞘翅、烟花和珍珠外，本套只放卓越前线物品。0.8.9.1 原生只注册头盔和胸甲，腿/脚为空；不会用原版护甲补齐。枪械原生明确禁用原版附魔，分级附魔作用于支持的近战武器、护甲与鞘翅。1–7 的普通近战仍沿用旧固定伤害表，不应用武器附魔；卓越前线刀剑未录入此表，当前低级近战只有其未知物品回退伤害。8–10 使用原版真实攻击与武器附魔。1 级无附魔，此后每一级增加附魔总量；10 级达到原版合法最高等级，遵守互斥规则。原版 10 级是完整下界合金 OP 套、满附魔剑斧/重锤/弓/鞘翅及有限图腾，弓选择无限、重锤选择致密。

医疗包实际使用 40 tick 后由原生物品治疗并消耗，面包壳沿用原生食物流程。当前自动补给仍遵守 8–10 级恢复能力门槛。配装中的装甲板、手雷、烟雾弹、C4、TM-62 与起爆器已列入库存，自动使用这些物品仍待后续专项实现；携带不代表 AI 已能操作。预设或手动更换配件、弹种继续生效。模组缺失或版本不兼容时不能选择 warfare；移除模组后已保存的 warfare 默认设置暂回退原版装备。

## 当前行为

| 等级 | 枪械控制 |
|---|---|
| 1–3 | 身体瞄准、较大误差、较慢转身、不主动开镜；打空再换弹 |
| 4–6 | 按距离选择已有枪种；边射击边横移，偶尔跳跃；空地换弹也会走动 |
| 7–9 | 瞄头、提前量、重力补偿；尝试掩体露头/回缩和安全换弹；8–9 低血补给 |
| 10 | 在相同枪械参数下提高操作精度；生成备弹，弹匣仍会打空，换弹和拉栓时间仍真实存在 |

- 枪械使用卓越前线原生开火、弹药、热量、拉栓和换弹流程，生成真实弹丸、音效和伤害；不直接扣目标血量，不修改枪械数据，不提高机器人运动速度。
- 换弹期间保护真实主手，普通距离变化不会切枪，切枪至少间隔 40 tick 并带当前武器优先权。没有敌人时依次手持真实枪械，装满空枪或不满弹匣；无当前弹种备弹且空膛时可通过原生流程切换至背包已有弹种。没有直接写入满弹匣。较长换弹完成后短暂搜索实际观察过的位置，不更新隐藏敌人的位置。
- 枪械只控制主手、瞄准和扳机。追击、导航、挖掘和搭路继续运行，珍珠、重锤、盾、进食与鞘翅可以交接主手；适用条件与原有难度门槛保持一致。真实枪械交换进 0 号格，显示副本不参与开火，动作结束后保留真实枪械与组件。
- 枪械走位使用原有运动接口：霰弹枪主要在 8 格内、冲锋枪在 15 格内，步枪约 15–50 格，狙击枪约 50–90 格；实际枪械射程还会限制范围。超出偏好距离会走近；进攻珍珠和飞行还须当前枪械够不到目标：霰弹枪有效攻击距离约 16、手枪 32、冲锋枪 40，步枪/狙击枪受原生射程与 160 格上限约束。步枪能打到 60 格时不会仅为拉近而飞到敌人身边。脱困、紧急撤离和抢位仍独立判断。8–10 贴脸且有真实近战武器时可切近战。7 以上尝试利用实际、可达且有射界的掩体，不凭空生成枪械掩体。低血战术仍可另行造临时掩体，恢复后可绕路重新找回最后看见的目标。
- 持枪的 1–9 级受视野和视线限制，失去视线后只保留限时最后已知位置。所有等级开火都要求目标实际可见，并限制每 tick 的转身角度。低难度瞄偏可以打到地面，失误不会被过滤成自动精准命中。
- 近距离优先已有霰弹枪或冲锋枪，中距离偏向步枪，远距离偏向狙击枪。数据读取运行时 GunProp，包含配件、弹药和数据覆盖的结果；射击范围当前最多 160 格。
- 当原有敌对目标乘坐载具时，4–10 调用载具本身的减伤计算比较已有武器。对子弹免疫的坦克不会继续使用步枪；有适合的 RPG 时可改用。7 级以上尝试从实际可达掩体预装、露头射击、发射后回缩；优先侧后射界，无法到侧后时有超时退出。开启合作且同队时分配短暂暴露的诱饵与分开的侧翼，伤员不承担诱饵暴露。友军乘员所在载具不射击。
- 开火前检查友军所在射线；爆炸武器还检查目标附近的友军和自身距离，按原生实体伤害最远为配置半径两倍留安全余量；实际瞄准射线在这个范围内撞到地面/近处掩体时也停火。这是发射前的安全判断，不能保证运动中的友军永远不进入已经发射的弹丸或爆炸范围。
- 全体机器人共享每 tick **64 颗弹丸**的开火预算，轮换等待，霰弹枪按实际弹丸数计费；每个机器人每 tick 最多一次开火。高射速或人多时实际射速可能降低；没有进行百人性能校准，也没有启用后台 AI 线程。

## 载具乘员与驾驶

先在世界中放好载具，并把准备共同乘坐的机器人和真人加入同一原版 scoreboard 队伍。座位从 **0** 开始，以卓越前线原生座位定义为准。命令安排靠近和登车，不生成载具、不抢真人座位，也不跨墙强制登车。

```mcfunction
/team add assault
/bot team assault Pilot
/bot team assault Gunner
/bot vehicle crew Pilot nearest
/bot vehicle status Pilot
/bot vehicle go Pilot 120 -60 80
/bot vehicle leave Gunner
```

- `crew <队长> <nearest|UUID>`：安排队长及其 32 格内、同队且具备登车能力的机器人，优先预留驾驶位，再按空位分座。`nearest` 搜索 32 格内未上锁、未损毁且没有敌方乘员的载具；指定 UUID 也须在同维度 48 格内。只安排有资格的空位，载具容量限制人数。
- `board <机器人> <nearest|UUID> [座位编号|auto]`：指定单个机器人座位；登车接近采用普通走路，通道需可达。正在接近的乘员会预留座位，驾驶员短暂等待装载；接近失败约 20 秒后退出安排。
- `go <驾驶员> <x> <y> <z>`：已安排的 0 号驾驶位前往绝对坐标；目的地必须在当前加载区域及世界边界内。地面车尝试短距离避障并停车；直升机尝试起飞、前往并降落。道路、复杂地形与落点仍需人工内测。
- `leave <机器人>`：地面离席；空中直升机乘员请求离席时由机器人驾驶员先尝试降落。真人驾驶的直升机需真人降落，机器人乘员会继续留在机上等待。损毁且有鞘翅时可以尝试弃机滑翔。不会为了完成命令而瞬移或强行在高空退出。
- `status <机器人>` 或 `/bot info <机器人>`：查看实际座位、登车状态、座位射击次数及驾驶阶段。射击次数记录请求，功能测试另外捕获真实弹丸与伤害。

| 能力 | 难度与开关 |
|---|---|
| 地面驾驶、命令登车、同队补座 | 7–10，`vehicles` |
| 操作实际座位武器 | 4–10，`vehicleweapons`；非固定载具命令登车仍需 7 级 |
| 直升机驾驶 | 9–10，`vehicles` 和 `helicopters` |
| 开放座位的随身枪械 | `guns`；遵守原生 `BanHand`、封闭状态和头部转动限制 |

可用 `/bot settings ability vehicles false`、`vehicleweapons false` 或 `helicopters false` 关闭，也可写进装备预设的能力档案。关闭驾驶能力后机器人停止接管驾驶按键；空中的乘员不会直接被甩出。

自主撤退、站位、绕侧、珍珠落点和飞行目标都约束在边界内并留余量。地面载具撤退使用有终点的目标，结合惯性提前发出原生刹车；不会不断重算向外的撤退点。低血载具先用原生减伤判断敌人是否构成威胁，对伤不到自己的近战步兵继续攻击。12 格内有安全路径时可原生驾驶碾压；非爆炸机枪可以瞄准近处步兵，主炮仍保留爆炸安全距离。车载射线排除同车乘员，随身枪仍检查同车友军。`status/info` 的 weapon 状态可区分原生装弹等待、瞄准与射线/爆炸安全等待。

座位和武器从运行时数据读取，每人只操作自己的座位。枪炮复用原生炮口、炮塔转动、座位射界、弹药、热量、换弹和延迟发射。等待延迟弹丸生成期间保持武器和座位，避免中途换炮使预留弹丸数失效。驾驶只发出原生按键/鼠标输入，速度、位置、转动和升力由卓越前线计算。机器人乘坐期间的移动由载具定位，自己的步行与重力不再干扰载具。

9 级及以下须给载具真实燃料和弹药。10 级机器人驾驶时补充原生能源，10 级炮手补充自己座位的原生备弹，仍保留换弹、过热和发射间隔；退出或降级会清理赠送储备。没有提升载具血量或机动力。直升机有基本攻击接近、拉离、障碍爬升和低燃料降落，并可对已发射的真实制导威胁使用原生诱饵；诱饵对抗效果尚未专门验证。

已验证载具为 M1A2、BMP-2、AH-6、Mi-28；其他采用相同座位/武器/轮式或履带式引擎的载具按数据接入，尚未逐辆实测。固定翼飞机、飞艇、船只与无人机驾驶尚未接入；零座位火炮也没有操作流程。直升机控制仍属于内测，空地和平坦着陆结果不能保证复杂山地、建筑群或高速目标的表现。

## 已验证与后续范围

功能自测使用真实 0.8.9.1 JAR：AK-47 真实伤害与有限库存弹药、AWM 拉栓和命中、AA-12 与 AWM 按距离切换、RPG 对真实 M1A2 的伤害、原生换弹空窗、物品组件/引用恢复、运行时数据覆盖，以及 12 人霰弹枪弹丸预算和公平轮换。新增真实位移、两队相距 60 格且从空 AK/AA-12 开始的 5v5、枪械/技能交接、载具分座、原生驾驶和多类座位开火场景。4.14 增加边界、双空枪、逐枪预装、同车主炮对照、近距离机枪/真实碾压、掩体 RPG 伤害、7 级长换弹后的实际重新接敌、反坦克诱饵/侧翼、原生医疗包及两套分级装备检查。驾驶员单人/双乘员对照均发炮，未复现原反馈推测的车长阻挡；不能据此认定偶发不开炮已完全定位。最新实际结果见 `AI_HARDNESS_PROGRESS.md` 与交付包中的验证日志。

其他普通枪械按相同 API 和运行时数据接入，但尚未逐枪实测。特殊枪种、蓄力/能量等特殊开火流程暂不接管。导弹锁定已设置持续瞄准时间、角度、距离和目标高度条件，但标枪/IGLA 的实际制导及各类诱饵反制尚未完成专门实测，不作为本批已验证能力。低速抛物线武器的提前量为有限近似，复杂移动目标仍需人工校准。

无人机、手雷/C4/烟雾弹、迫击炮间接射击、车长雷达、军事喊话、步兵兵种与 10EX 指挥系统仍待后续实现；原始规划见 `docs/superbwarfare-compat-notes.md`。现有难度仍为 1–10。

开发期间反馈文件新增了链接的完整版 `docs/playtest-report-4.13.md`（2026-10-05 08:01 更新）。其新增直升机固定武器俯冲扫射、对空威胁规避/乘员射界、丢失目标后的载具回场、机尾登车绕行和多车编组建议尚未完成。本轮直升机仅新增边界目标与惯性转向限制，没有把这些新条目标记为通过。低级乘员上车与有限补给开关也仍待用户决定。

## 开发者验证

基础回归不安装卓越前线，仍用最小 NeoForge：

```powershell
$env:JAVA_HOME='C:/Program Files/Microsoft/jdk-21.0.7.6-hotspot'
.\gradlew.bat build --console=plain
.\gradlew.bat runSelfTest --console=plain
```

集成验证使用隔离目录中的卓越前线和 Kotlin for Forge JAR。另建超平坦自测目录，接受 EULA 并设置与正式服不同的端口；本工作区使用 25600。以下两个目录参数相对于仓库根目录：

```powershell
.\gradlew.bat runSelfTest '-PselftestFocus=warfare' '-PwarfareModsDir=../../work/warfare-test-mods' '-PselftestDir=../../work/warfare-selftest' '-Pneo_version=21.1.249' --console=plain
```

集成测试不把第三方 JAR 打进产物。最后在默认 21.1.1 再构建；不能把一次临时较新版本编译的 JAR 当作最低版本兼容产物。功能汇总必须查看 `[SelfTest]`，Gradle 成功不等于场景通过。
