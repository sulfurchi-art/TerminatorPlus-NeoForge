# 下一批：对手习惯学习（待实现）

此文件是开发准备笔记，不表示以下机制已经实现。4.10 最终完整回归期间不修改参与构建的 Java 源码。

当前 `OpponentLearning` 只有对真人 UUID 保存的招式尝试/命中计数；`EliteCombat` 读取当前举盾、进食、攻击冷却、起飞与落地状态。把即时状态描述为已经学会长期习惯，会超出现有证据。

建议先实现范围有限且可以被真实事件证实的三类习惯：

- 移动：把连续可见位置变化投影到机器人到对手的水平连线，记录左/右侧移和远离趋势；排除传送、维度切换、同 tick 重复观察和机器人目标。单次侧移不能立即形成结论。
- 举盾：只记录实际生效的原版格挡状态进入/退出；在已确认的真人攻击、恢复或破盾事件后开短期观察窗，统计窗口内是否举盾。区分正在使用盾和已经超过原版启用时间的盾。
- 补给：以原版真实物品使用开始和完成为依据，记录开始时血量区间、是否先撤离；不把持有金苹果、库存数量或一段静止当作实际恢复行为。

状态分两层：每世界有限真人档案保存习惯摘要；每个战斗会话只保存短期观察窗口和采样游标。多个机器人观察同一真人时，以世界 tick 和事件身份去重，避免人数越多结论越强。没有样本、样本不足或样本矛盾时继续用现有默认决策。

决策接入只调整合法候选招式的权重、现有落点目标和假动作选择。预测有界且保持探索概率；不增加移动、攻击触及、攻击次数、血量或伤害。真实恢复和受压优先级保持不变。

持久化需兼容现有招式结果 SNBT，新增数据版本和计数验证；在临时结构中完整解析后交换，避免畸形条目造成半份档案生效。有上限、衰减、过期与离线清理。第一次只接明确的习惯类别，不接无证据的“读懂你”台词槽位。

自测需要真实 ServerPlayer 夹具、真实盾牌/食物进度和实际移动；覆盖左右/撤离习惯、跳变排除、重复观察、样本不足、对手更换、持久化迁移、取消或未完成的使用、8–9 无习惯预测，以及实际选择改变和保命中断。统计判断和功能判断分开，不把功能场景当成赢率证据。
